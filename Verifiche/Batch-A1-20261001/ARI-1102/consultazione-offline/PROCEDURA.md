# ARI-1705 — Progettazione prompt per agenti

- **Categoria:** Intelligenza artificiale
- **Livello:** L4 Avanzato
- **Stato:** Bozza verificabile
- **Versione:** 0.1.0
- **Utilizzo offline:** Sì

## Scopo

Creare, correggere e migliorare prompt per agenti IA, trasformando richieste grezze in istruzioni operative chiare, riutilizzabili, verificabili e coerenti con il progetto.

## Campo di applicazione

Prompt di sistema, prompt operativi, istruzioni per agenti specializzati, ruoli, vincoli, formati di risposta, criteri di completamento, uso strumenti, limiti di autorizzazione e prompt riutilizzabili per flussi locali.

## Quando usarla

- quando l'utente chiede di creare un prompt per un agente
- quando un prompt esistente va corretto, ampliato o reso meno ambiguo
- quando serve definire ruolo, compito, strumenti, limiti e formato di uscita
- quando una richiesta confusa deve diventare istruzione operativa
- quando serve rendere ripetibile il comportamento di un agente

## Quando non usarla

- quando basta correggere un testo normale senza logica agente
- quando l'utente chiede esecuzione diretta del compito, non progettazione del prompt
- quando il prompt richiederebbe permessi, accessi o azioni non autorizzate
- quando il dominio richiede competenze specialistiche non disponibili nel contesto

## Prerequisiti

- obiettivo dell'agente
- contesto operativo e strumenti disponibili
- vincoli di sicurezza, privacy, licenze e autorizzazione
- formato di uscita desiderato
- criteri per capire quando il compito e completato
- esempi positivi o negativi, se disponibili

## Materiale necessario

- descrizione del compito
- destinatario o ambiente dell'agente
- eventuale prompt di partenza
- regole obbligatorie e divieti
- esempi di input e output attesi
- limiti su tono, lunghezza, lingua e autonomia

## Procedura operativa

1. Chiarire quale agente deve essere creato: scopo, dominio, autonomia e confini.
2. Separare ruolo, obiettivi, strumenti, vincoli, criteri di uscita e formato risposta.
3. Eliminare ambiguita, comandi contraddittori e istruzioni troppo generiche.
4. Definire cosa l'agente puo fare, cosa deve chiedere e cosa deve rifiutare o rimandare.
5. Scrivere il prompt in italiano tecnico, con sezioni leggibili e istruzioni verificabili.
6. Aggiungere esempi solo se migliorano il comportamento previsto.
7. Verificare il prompt con una richiesta di prova o con una checklist di coerenza.

## Controlli

- obiettivo dell'agente esplicito
- confini e permessi non ambigui
- formato di risposta definito quando serve
- criteri di completamento verificabili
- assenza di istruzioni contraddittorie
- tono coerente con il progetto e con l'utente

## Errori frequenti

- creare prompt troppo lunghi ma senza criteri operativi
- confondere ruolo dell'agente con lista generica di desideri
- non distinguere autorizzazioni, strumenti e limiti
- promettere accessi o capacita non disponibili
- non indicare quando fermarsi o chiedere chiarimenti

## Rapporto finale

Restituire il prompt pronto all'uso. Quando utile, includere una breve spiegazione della struttura, una checklist di verifica e una variante compatta.

## Condizioni di uscita

- prompt utilizzabile senza riscrittura ulteriore
- ruolo, obiettivo e limiti chiari
- formato di uscita definito
- criteri di completamento presenti
- rischi o ambiguita residue segnalati
