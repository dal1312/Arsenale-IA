## Rilievi prodotti

### OFL-001 — README legacy in conflitto con la documentazione corrente

- **Priorità:** P2
- **Categoria:** documentazione/manutenzione
- **Evidenza:** nella radice coesistono `README.md` e un file `README` senza estensione. `README.md` descrive il candidato `0.12.0-rc1`, flussi di audit, Redis, unlearning evidence e stato attuale; `README` descrive ancora un prototipo precedente e contiene note produzione non allineate al progetto corrente.
- **Impatto:** strumenti automatici, pacchetti o operatori che leggono il file legacy possono ricevere istruzioni e limiti obsoleti.
- **Correzione consigliata:** eliminare il file legacy dopo confronto finale oppure sostituirlo con un rinvio inequivocabile alla documentazione canonica.
- **Test richiesto:** ricerca di riferimenti al file `README` e verifica del pacchetto/repository dopo la rimozione.
- **Rischio modifica:** basso.

### OFL-002 — Stato CI del commit corrente non dimostrato da una run verde

- **Priorità:** P2
- **Categoria:** CI/rilascio
- **Evidenza:** il commit corrente è `[skip ci]`; l'ultimo release gate osservato è verde su una revisione precedente e le modifiche successive sono documentali, ma l'ultima run del workflow principale individuata su un commit intermedio è fallita su entrambi i sistemi operativi.
- **Impatto:** non è corretto dichiarare `main` attualmente verde basandosi solo sul release gate precedente, anche se non risultano cambi al codice dopo quel gate.
- **Correzione consigliata:** rieseguire la CI principale sul commit corrente o su un commit equivalente, conservare il risultato e investigare l'ultima failure se si ripresenta.
- **Test richiesto:** `Omega FL CI` verde su Ubuntu e Windows; release gate coerente prima della prossima release.
- **Rischio modifica:** nessuno per il rerun; da valutare se emerge una correzione.

### OFL-003 — Base image Docker non immutabile

- **Priorità:** P4
- **Categoria:** riproducibilità
- **Evidenza:** `Dockerfile` usa `FROM python:3.12-slim` senza digest.
- **Impatto:** build effettuate in momenti diversi possono risolvere a immagini base differenti.
- **Correzione consigliata:** valutare pin per digest nel percorso di release, con processo esplicito di aggiornamento.
- **Test richiesto:** rebuild dell'immagine e controlli release dopo l'aggiornamento.
- **Rischio modifica:** basso-medio.
