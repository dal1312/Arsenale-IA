## Rilievi prodotti

### AIA-001 — Termini di riuso non espliciti

- **Priorità:** P3
- **Categoria:** distribuzione/documentazione
- **Evidenza:** nessun file `LICENSE`, `LICENSE.md` o equivalente nella radice ispezionata.
- **Impatto:** il repository è progettato per essere riutilizzato, ma i termini di riuso non sono dichiarati nel progetto.
- **Correzione consigliata:** scegliere e aggiungere una licenza coerente con l'obiettivo del progetto.
- **Test richiesto:** controllo automatico o checklist di rilascio che ne confermi la presenza.

### AIA-002 — Versioni di roadmap non materializzate in tag/release

- **Priorità:** P3
- **Categoria:** rilascio
- **Evidenza:** API GitHub di tag e release entrambe vuote durante la prova.
- **Impatto:** v0.3 e v0.4 sono dichiarate completate nella roadmap ma non esiste un riferimento di rilascio immutabile facilmente consumabile.
- **Correzione consigliata:** introdurre tag/release quando viene stabilita una politica di versione del progetto complessivo.
- **Test richiesto:** ARI-0010 prima della prima release formale.

### AIA-003 — Glossario non allineato alle nuove funzioni

- **Priorità:** P4
- **Categoria:** documentazione
- **Evidenza:** il glossario non definisce Agent Skills, `SKILL.md`, conformità strutturale, versione semantica delle procedure o verifica operativa.
- **Impatto:** riduce la comprensibilità per nuovi contributori, pur non compromettendo il funzionamento.
- **Correzione consigliata:** ampliare il glossario durante la v0.5.
- **Test richiesto:** revisione documentale.

### AIA-004 — Nome storico del workflow

- **Priorità:** P4
- **Categoria:** manutenzione
- **Evidenza:** il file `.github/workflows/verifica-skills.yml` ora verifica l'intero Arsenale, non solo le skill.
- **Impatto:** lieve disallineamento tra nome file e responsabilità effettiva.
- **Correzione consigliata:** rinominare il workflow file in una futura modifica coordinata.
- **Test richiesto:** GitHub Actions verde dopo la rinomina.
