- I test saltati sono `test_mounted_file_provider_rejects_symbolic_links` e `test_mounted_file_provider_rejects_world_readable_file_when_strict`.
- Il secondo è decorato con `skipif(os.name == 'nt', reason='POSIX permission bits required')`; il primo salta quando la creazione del symlink non è disponibile.

- Non è stato rilevato un report di coverage nel comando di validazione analizzato; nessuna conclusione viene basata su una percentuale inesistente.

## Rilievi prodotti

### OFL-TST-001 — Controlli filesystem POSIX del secret provider non esercitati dalla CI principale Windows

- **Categoria:** comportamento critico non coperto nel percorso CI analizzato
- **Priorità:** P2
- **Area:** `tests/unit/test_secret_provider.py`
- **Evidenza:** i test su symlink e permessi world-readable sono entrambi skipped; il workflow principale usa un runner Windows self-hosted.
- **Impatto:** la pipeline corrente non dimostra automaticamente che le protezioni filesystem specifiche POSIX continuino a rifiutare symlink e file con permessi troppo aperti.
- **Test proposto:** job Linux dedicato che esegua almeno questi test; input: symlink verso secret e file `0644` con strict permissions; risultato atteso: `SecretProviderReadError` in entrambi i casi.

### OFL-TST-002 — Test del release gate troppo accoppiati al testo del sorgente

- **Categoria:** test troppo accoppiato all'implementazione
- **Priorità:** P2
- **Area:** `tests/unit/test_release_gate_workflow.py`
- **Evidenza:** molte asserzioni verificano stringhe, marker e ordine di testo; il test del Redis gestito controlla la presenza/posizione delle chiamate invece del comportamento degli helper.
- **Impatto:** refactoring semanticamente corretto può rompere il test, mentre alcuni errori comportamentali possono non essere rilevati se le stringhe attese restano presenti.
- **Test proposto:** monkeypatch/mock di ambiente, `_redis_ping`, `subprocess.run` e `time.sleep`; casi: fuori da GitHub Actions, Redis già disponibile, start riuscito+cleanup, start fallito, timeout readiness e cleanup.
- **Nota:** il rilievo era già emerso nella code review ARI-0002 ed è qui confermato come classificazione di qualità della suite.

### OFL-TST-003 — Deprecation warning ancora presenti nella suite

- **Categoria:** manutenzione test
- **Priorità:** P4
- **Evidenza:** 2 warning nella run completa, relativi a TestClient/httpx e allo status HTTP 422 deprecato.
- **Impatto:** non invalidano la suite corrente ma segnalano compatibilità futura da gestire.
- **Test proposto:** aggiornare dipendenze/API in un intervento separato e portare la suite pertinente a zero warning deprecati noti.
